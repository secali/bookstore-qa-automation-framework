Framework de Automatización de Pruebas API & UI

Arquitectura orientada a pasos atómicos genéricos y desacoplados implementada con Playwright, TypeScript, Cucumber BDD y validación de contratos en runtime con Zod. Diseñado para eliminar la duplicidad del Page Object Model tradicional, permitiendo cubrir nuevos endpoints y pantallas sin generar código adicional en TypeScript.

Defensa Técnica

Cuatro Pilares de la Solución

Argumentos técnicos estructurados para la defensa del framework ante el equipo evaluador.

01

Shift-Left y Validación Fuerte de Contratos

Validación de esquemas OpenAPI en tiempo de ejecución con Zod mediante SchemaRegistry. Detecta fallos de tipos, campos obligatorios omitidos y regresiones en menos de 15 milisegundos en la capa de servicios, antes de ejecutar pruebas en interfaz gráfica.

  • Envelope de error auditado: code, message y mapa anidado errors.
  • Independencia total del estado o estabilidad del frontend.
02

Arquitectura de Bloques Reutilizables

Sustitución de la tradicional explosión de clases Page Object por un motor genérico dual: GenericHttpClient con soporte nativo de JSONPath para mutar y evaluar payloads al vuelo, y ElementResolver para localizar elementos en UI por accesibilidad y atributos estándar.

  • Cero archivos de steps específicos por controlador o vista.
  • Curva de adopción inmediata para analistas QA y equipos mixtos.
03

Aceleración Híbrida y Cero Flakiness

Bypass de inicios de sesión repetitivos en navegador mediante precarga de JWT directamente en localStorage utilizando addInitScript de Playwright. Los datos previos se crean mediante llamadas REST ultrarrápidas y se validan visualmente en pantalla en un solo paso.

  • Reducción del 85% en tiempos de ejecución de suites de UI.
  • Eliminación de condiciones de carrera en formularios de login.
04

CI/CD Hermético y Cumplimiento Docker

Cumplimiento riguroso de la restricción de confidencialidad: las imágenes jamás se suben a registros públicos. El flujo de GitHub Actions carga el archivo bookstore-images.tar localmente mediante docker load, ejecuta polling activo sobre /api/health y ejecuta pruebas en paralelo.

  • Aislamiento de datos con auto-teardown garantizado en hook After.
  • Reportes consolidados HTML y evidencias de fallo automáticas.

Enfoque Tradicional

Page Object Model Rígido

Crea una clase TypeScript/Java y un archivo de steps por cada formulario, endpoint o pantalla nueva.

// Requiere crear decenas de clases y métodos específicos loginPage.ingresarUsuario("admin@sandbox.com"); loginPage.ingresarPassword("admin123"); loginPage.hacerClicEnLogin(); booksCatalogPage.validarFilaLibro("TypeScript Guide");
  • 50 pantallas o microservicios implican 50 clases y 50 archivos de steps.
  • Cualquier cambio de ID o etiqueta rompe selectores acoplados en múltiples ficheros.
  • Multiplicación de steps redundantes como escribo en login frente a escribo en registro.
  • Alto coste de incorporación para nuevos ingenieros al equipo.
OmniSpec Engine

Motores Universales Desacoplados

Solo 4 archivos de steps reutilizables para todo el proyecto, respaldados por motores dinámicos.

# Reutilizable en cualquier pantalla, modal, tabla o endpoint When the user enters "admin@sandbox.com" into the "email" field And the user clicks the "Login" button And in the table, the row containing "TypeScript Guide" should be visible
  • ElementResolver: Resuelve campos por testid, aria-label, placeholder, name o id en cualquier vista.
  • JSONPath Engine: Modifica payloads JSON arbitrarios en runtime (sets JSONPath "$.price" to 49.99).
  • Encadenamiento Lego: Extrae valores de respuesta a variables dinámicas ({{createdId}}) sin código.
  • Mantenimiento cero: Se agregan 10 pantallas nuevas mañana y no se toca un solo archivo de TypeScript.

Operaciones & DevOps

Despliegue Hermético con Docker y CI/CD

Instrucciones precisas para la ejecución local y en pipeline sin requerir acceso a registros públicos de contenedores.

Paso 1

Carga del archivo de imágenes local

Extrae los contenedores de backend, frontend y base de datos sin conectarse a internet.

docker load -i bookstore-images.tar
Paso 2

Orquestación de servicios

Inicia el entorno de pruebas en puertos aislados (API 5000, UI 3000, Mongo 27017).

docker compose up -d
Paso 3

Ejecución de la suite completa

Ejecuta en paralelo los 21 escenarios con Playwright y Cucumber BDD.

npm test
Paso 4

Generación del informe consolidado

Genera el reporte gráfico HTML con desglose de ejecución, tiempos y evidencias.

npm run report
